## 1. Evidence and objective

On 2026-11-27 the Cloudflare dashboard showed 5.93M SQL rows read, 11.61k rows written and 3.77k DO requests. Runtime explicitly rejected SQL initialization with `exceeded allowed rows read in durable objects free tier`. The historical cause was repeated full operation-journal enumeration and materialization (up to nine traversals per idle poll). PR #22 replaced those scans with indexed projections, bounded maintenance and quota-aware connectivity backoff. The provider quota is account-level and cannot be reset by software. As of the recorded deployment probe, Worker 0.1.12 was live but readiness returned 503. No inference of lost pairing is warranted.

### O05 — Hibernatable WebSocket notifications, HTTP remains execution authority

**Dependency:** O04. **Outcome:** eliminate routine idle work-fetch polling on healthy connections without rewriting the MCP protocol.

Protocol design:
- Keep existing HTTP `/api/v1/tab/poll` and all execution/permit/reply routes compatible. Add a versioned optional notification capability, negotiated by authenticated claim/heartbeat or capability response. Legacy client, unsupported runtime, disabled feature, handshake failure or socket loss uses existing bounded HTTP polling. Feature flag/rollback must disable push without schema downgrade; initial candidate ship with conservative default (push opt-in until operator live test), not a placeholder. Test both flag states; document exact activation setting.
- Use Cloudflare `acceptWebSocket`/hibernation handlers, socket attachments (only minimal nonsecret scope/lease/session-generation metadata), no regular `accept()` or recurring DO timer. Validate Origin as defense-in-depth, not identity. WebSocket browser constructors cannot set arbitrary Authorization headers: design authenticated POST ticket (short TTL, single use, high-entropy, bound to exact lease/workspace/epoch/tab, stored as digest, consumed atomically) or first-message proof of lease using an isolated userscript context. Prefer a design avoiding credentials/tickets in URL, query strings, telemetry or page code. If a URL ticket is unavoidable, explicitly justify, make it one-time/short-lived and prove redaction. Unauthenticated sockets have strict count/time/message-size limits and no storage reads beyond necessary authentication; do not allow idle unauthenticated sockets to leak capacity. Never expose admin/execution credential or source to Perchance page. Verify socket API isolation and CSP behavior in synthetic fixtures; actual Violentmonkey/CSP compatibility remains operator live gate.
- Message vocabulary is small, versioned and data-minimal: authenticated ready/availability notification, optional monotonic queue revision or sequence hint, bounded keepalive/ack/control. Notification never delivers an operation, payload, capability or effect permit; it is advisory only. Persist admitted operation before notifying, then notify after commit. Dropped/duplicated/out-of-order messages do not affect canonical state. On connect/reconnect perform immediate authoritative fetch (no lost-wakeup gap between subscribe and snapshot), coalesce notification bursts, maintain at most one fetch/execution loop per lease generation. If a signal arrives during fetch/execution, latch a rescan bit until drain reaches stable empty; do not start parallel execution. Heartbeat or bounded reconciliation must recover missed wakeups even if socket falsely appears open. Prefer piggyback `workAvailable` on existing authoritative heartbeat, preserving <=60s recovery bound for silent notification loss; normal healthy idle sends no extra work-fetch HTTP traffic. On disconnect immediately switch to bounded fallback, reconnect with jitter/backoff, negotiate safely, cancel stale loops. Browser timers throttled/suspended are not proof of revocation. Reject stale socket generation after reconnect, pause/release/rebind/epoch change. Do not dispatch from stale attachment or rely on notification delivery for liveness. Set bounded reconnect and outstanding handshake limits.
- Keep current lease and policy renewal semantics until measured equivalent consolidation. Protocol ping/automatic response may assist transport liveness but never extend lease or prove current authority. Heartbeat and fallback remain available. Notification cannot bypass current Registry dispatch permit or local source revision checks. Hibernation discards memory; reconstruct socket registry from runtime sockets and validated attachments, recheck canonical lease before sending any work signal. Deployment, eviction, duplicate sockets, stale tickets, connection floods, reconnect, dropped notifications, pause and revocation must be tested offline. Do not use persistent connection as a transaction or an operation stream.

**Gate:** local workerd WebSocket tests plus synthetic userscript integration; no pending I/O/timers that unnecessarily prevent hibernation, no unbounded socket allocations, idle no periodic work-fetch calls, fallback unchanged, no operation loss/replay or parallel execution. Demonstrate local wakeup latency and missed-wakeup bound. Physical Cloudflare hibernation/billing and real Firefox/Violentmonkey acceptance explicitly deferred.

### O07 — Quota-aware admission, failure containment, final integration and handoff

**Dependency:** O01–O06. **Outcome:** predictable resource budget, emergency recovery headroom and complete offline release candidate.

1. Implement conservative gateway-owned budget accounting and admission control, not a claimed authoritative Cloudflare quota meter. Model dimensions separately (reads, writes, requests, duration proxy, storage, KV, logs). Use configurable caps below provider limits, fixed UTC-day identity, conservative reservations for admitted operation completion including worst-case bounded payload cost, retries and deferred cleanup; carry obligations across midnight and handle clock skew, restarts, failed counter writes, unknown/missing counters and other account traffic. Integrate admission reservation with existing canonical writes/transactions where practical. Avoid one additional persistent counter write per ordinary read, global quota RPC on every idle poll, or per-isolate accounting treated as global truth. Prefer Registry durable allocation of per-Workspace bounded envelopes plus conservative batched usage reconciliation or simpler equivalent proven to bound aggregate exposure. Document exact overshoot bound, reconciliation/expiry, migration and cost. If reliable global bound cannot be guaranteed without excessive complexity, enforce local conservative bounds and clearly label account-wide estimates; never assert hard reservation of provider capacity.
2. Policy proposals: <50% normal; 50–70% enhanced visibility; 70–85% reduce optional refresh/soft maintenance; 85–95% restrict expensive/new operations; >=95% deny new nonessential admission, preserve completion/reporting/recovery. Explicitly distinguish necessary safety maintenance (active expiry, outbox, hold reconciliation) from optional work; no delaying required expiry or permission checks. Never reject a valid terminal result solely due to internal budget policy; if provider rejects persistence, retain recoverable evidence and surface unknown/unavailable, not success. Reserve resources for safety before admission, not after effects start. Do not poll account analytics from hot path; operator may supply measured external consumption after reset. No auto-upgrade or external account access. Test day rollover, concurrent reservations, restart, failed persistence, stale/unknown accounting and quota fault at each transition.
3. Audit failure cascade: `incident.ts` uses `OAUTH_KV` for infra-incident writes with isolate-local dedup; one outage can consume OAuth KV allowance. ## 5. Migration, rollback and transition protocol (O03/O04/O06)

An additive migration is not automatically reversible. Old binaries understand the canonical `records` representation and dirty triggers, not arbitrary new schemas. Explicitly design forward and reverse compatibility for each domain. The operator must approve deployment and any irreversible step.

| State | Canonical authority | Allowed behavior |
|---|---|---|
| LEGACY | legacy records | old/new reader compatible; no new-only writes |
| PREPARE/BACKFILL | legacy records | additive shadow schema; bounded resumable migration; mirror relevant writes or track dirty keys transactionally |
| VERIFY | legacy records | compare typed projection and complete canonical semantics, payload hashes, counts, revisions, unresolved holds and receipts; drain/check dirty set under transaction |
| CUTOVER | new schema after atomic version marker | single transaction per DO verifies generation and switches authority; no mixed reads within request |
| NATIVE | new schema | all new writes target new authority; old binary rollback forbidden unless reverse compatibility is maintained |
| ROLLBACK_PREPARED | current verified authority | quiesce only new admission where necessary, drain/reconcile without replay, materialize reverse format from latest canonical state, verify, atomically switch marker; never restore stale snapshot |
| CORRUPT/BLOCKED | last known authority, no guessed fallback | fail closed with diagnostic; preserve state, operator recovery procedure |

Requirements:
- Versioned schema tables and persisted migration cursor/state, checksums/counts/semantic verification as appropriate, bounded work by row/byte/time budget. Preserve existing DO IDs and bindings, not re-create classes. Canonical old format may have multi-part JSON, explicit nulls, pending and resolved holds, unknown effects, retired leases, old trigger definitions and partially initialized derived metadata. Cover empty/unpaired as well as populated objects. Reject invalid schema/version, do not default corrupted record. Preserve missing vs null semantics, all canonical fields, ordering, retention deadlines, raw payload hash and exact public projections. Build against pinned old version fixtures.
- While backfilling, existing behavior can continue against legacy authority. Dirty tracking must catch old binary writes, updates/deletes and rollback conflicts; no missed keys. Avoid unbounded sync at first request after reset: small batches, durable progress, schedule with backoff, explicit progress diagnostic; account for migration budget. Cutover is local atomic, not cross-DO atomic. Define compatibility of mixed Registry/Workspace versions and forward/backward wire shapes. If operation crosses migration boundary, identity/fences and exact transaction semantics remain valid. No cutover while unsafe active state would be lost. Use feature flags to gate adoption/cutover separately, ensure migration completion is not dependent on live traffic. Old userscript must keep HTTP working.
- Pre-cutover rollback: disable new path, use untouched legacy records. Post-cutover rollback: either verified reverse migration or compatible rollback binary retaining new canonical reader. A stale retained legacy snapshot is NOT a valid fallback. Do not leave permanent dual writes. Do not delete legacy data automatically on first launch; define retention/cleanup after operator approval and successful live acceptance; account for temporary duplicate storage and write cost. No restore to a pre-effect snapshot without reconciliation. Do not claim generic provider PITR is safe rollback of external effects.
- Test kill/restart between every migration state; failed SQL statements/transactions, quota mid-batch, duplicate retry, stale cursor, concurrent mutation, malformed records, mixed versions, rollback after new writes and partial migration across multiple Workspaces. Compare public responses and internal safety state. Document version/feature flag activation, failure recovery and reverse procedure using local fixtures. Do not execute migration against production during this program.
