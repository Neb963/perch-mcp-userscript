# Setup and operator experience contract

This is the intended release UX, not a working deployment guide yet.

## First installation (dashboard-first)
1. Open release README and click Deploy to Cloudflare. Use official Deploy button for public repository with pinned reviewed release branch/tag where supported. Cloudflare creates/imports deployment repository and provisions declared bindings. If button cannot deploy pinned ref, provide released source archive and dashboard Git integration to exact release branch. Do not auto-deploy development main. User needs Cloudflare account and Workers enabled. No custom domain required; workers.dev HTTPS default.
2. Deployment config declares SQLite Registry and Workspace Durable Object migrations and OAuth KV binding; no manual database creation if official deployment flow succeeds. Required secret BOOTSTRAP_SECRET entered in deployment UI using password-manager generated >=32 random bytes (base64url/hex); .dev.vars.example lists only placeholder. A dashboard-only fallback identifies exact Settings > Variables and Secrets and Bindings actions; if actual platform cannot provision DO migrations in UI, provide one-command Wrangler fallback solely for deployment, never a runtime local bridge. P02 must validate actual clean-account workflow, including OAuth metadata URL, secret provisioning and release pin. No promise of a single pasted JS Worker: DO migrations and OAuth binding require configuration.
3. Worker opens /setup with health status only, no public auto-claim. Copy Worker HTTPS URL. Install released .user.js in supported Firefox userscript manager; .txt mirror available for manual install; no dependency downloads at runtime.
4. On Perchance editor, open Perch MCP from compact entry. Paste URL and bootstrap secret, pair. Wizard checks TLS, configured issuer, protocol version, adapter compatibility, management auth and browser transport. Secret consumed once; operator stores recovery procedure, not a token in URL. On failed pair show exact remedy without logging secret.
5. Import owner-provided skills-all.zip through Library. Preview 11 domain skills, skip report and OpenCode unless optional reference explicitly selected. Publish after review. Include provider-neutral agent instructions and default workflows in our own release.

## Each Agent (normal workflow)
Current editor -> Attach Workspace -> name Agent -> choose permission preset -> Create connector -> copy exact MCP endpoint -> add custom connector in AI web UI -> authorize -> manager shows pending client and code -> approve -> client completes callback -> test workspace_status -> ready. Copy buttons: endpoint, optional public client ID, documented required scope, setup instructions, optional client secret only for manually configured confidential client where necessary (separate one-time display). OAuth tokens generated and retained by client; optional scoped bearer token compatibility mode requires header support, separate expiration/revocation, never URL token. Userscript shows OAuth status, not provider login credentials. No external OAuth app registration per Agent. Multiple connectors for same provider supported if client allows distinct endpoint configuration. Same connector in multiple conversations shares Grant; no promise of conversation identity. Assign one connector to one agent/task at a time; collisions serialized and visible. A connector cannot silently change target: rebind revokes old Grant and requires fresh authorization.

## Day-2
Manager provides global kill switch, per-Workspace pause, disconnect/rebind, grant expiry/revoke, one-time credential copy, version check, export/import, quotas, redacted diagnostic ZIP, checkpoint recovery. No dashboard access required for routine operations. Cloudflare account needed for first install, deployment update, recovery and billing. Credential recovery: dashboard change RECOVERY_SECRET, run authenticated recovery flow, invalidates old credentials/leases/grants, preserves Resource registry, new pairing; consumed recovery nonce, never automatic reset. Backup resources before upgrade; pause and settle work; release upgrade wizard checks schema compatibility; rollback only to compatible Worker version and restore data separately if required. Native generator source backups local and independently exportable. No secret or bearer token in exported settings. Document exact setup screenshots after real verification; no invented screenshots now.

## Usability acceptance
Fresh owner can deploy with no local daemon/CLI on supported dashboard path; target <=10 minutes excluding account creation and provider consent, measured not guaranteed. After pairing, creating another connector requires no Cloudflare configuration and <=5 manager actions before external client setup. Every copy action gives exact value and clear feedback. Error state offers direct next action. Accessible keyboard/focus and one-scroll layout at 1024x768 and 1920x1080. No double scroll, overflow, page overlay intercepting editor outside open manager. Native editor remains operable when gateway unavailable.
